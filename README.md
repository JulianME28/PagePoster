# PagePoster Desktop

PagePoster — програма для Windows, яка готує сторінки з матеріалів проєкту й публікує їх на сайтах WordPress, якими ви маєте право керувати. Інтерфейс українською мовою.

## Початок роботи

Завантажте чистий Windows-випуск у розділі [Releases](https://github.com/JulianME28/PagePoster/releases), розпакуйте всю папку й запустіть **PagePoster.exe**. Для готового випуску Node.js і термінал не потрібні.

- [Ілюстрований гайд](docs/USER-GUIDE.uk.md) — від першого налаштування до публікації та ручної перевірки.
- [Гайд у PDF](docs/PagePoster-User-Guide-1.1-UA.pdf).
- [Навчальні приклади](docs/PagePoster-Guide-Examples.zip).

## Версія 1.1.0

- Повторне рішення про кошик після підтвердження, що незмінена сторінка все ще опублікована. Прострочені рішення не повторюють дію.
- Явне відкладання проблемної сторінки зі збереженням її ID та донора. Повернення до неї — окремою кнопкою.
- Імпорт сумісних аркушів XLSX та таблиць архіву зі збереженням координат джерела. Формули не виконуються; підтримуються перевірені скалярні кешовані значення.
- Нормалізація GEO, унікальність основного домену, пояснення й упорядковані резерви в ручному каталозі донорів.
- Окрема кількість карток і 22 мови генерації. Параметр cardCount також підтримується в таблицях проєкту.
- Налаштування Google на чистому профілі через локальний імпорт власної Desktop OAuth-реєстрації. У налаштованій збірці лишається звичайний вхід Google.

## Власні підключення

Публічний пакет не містить робочих проєктів, бази сайтів, паролів, API-ключів або OAuth-конфігурації команди. Додайте власний OpenAI API-ключ і підключіть свою базу сайтів. Якщо реєстрацію Google не налаштовано, отримайте Desktop OAuth JSON у відповідального за PagePoster або адміністратора Google Cloud та імпортуйте його в налаштуваннях. Також доступний сервісний акаунт.

Для стиснених архівів RAR5 потрібен установлений WinRAR у стандартній папці Program Files. ZIP можна імпортувати без WinRAR.

## Розробка та перевірки

Потрібні Node.js 24 і pnpm. Виконайте `pnpm install --frozen-lockfile`, потім `pnpm exec playwright install chromium`.

`pnpm test` запускає локальні тести й відмовляє, якщо файлів тестів немає. `pnpm test:full` вимагає браузер, непорожній набір виконаних тестів і повний успішний підсумок без TODO та неочікуваних пропусків.

Для legacy PHP-перевірок потрібен PHP 5.6; задайте повний шлях змінною `PAGEPOSTER_PHP56`. PHP 8.4 WASM установлюється як тестова залежність. Браузер можна явно вибрати змінними `PAGEPOSTER_PLAYWRIGHT_MODULE` і `PAGEPOSTER_CHROME`. Windows CI готує ці залежності автоматично.

Для збірки десктопа використайте `node scripts/build-desktop.cjs --clean`. Локальні конфігурації, ключі, робоча база та результати збірок виключені з Git. Тести містять лише синтетичні приклади й окремо позначений локальний TLS-ключ тестового сервера.
